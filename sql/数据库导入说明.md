# 数据库导入说明

本文档介绍如何将项目数据库导入到本地 MySQL，包含全部业务表结构和业务数据。

---

## 一、前置条件

- **MySQL 8.0+**（需支持 `utf8mb4` 字符集）
- 已将 `mysql` 和 `mysqldump` 命令加入系统 PATH，或知道其完整路径
- 如使用 GUI 工具（Navicat / DBeaver / MySQL Workbench），需已连接本地 MySQL 实例

---

## 二、SQL 文件说明

| 文件 | 内容 | 适用场景 |
|------|------|----------|
| `db_full_dump.sql` | **64 张表的完整 DDL + 全部业务数据**（约 645 KB） | **推荐**，导入后开箱即用，含全部客户/流程/审批/规则等业务数据 |
| `db_schema.sql` | 119 张表 DDL（仅结构，无数据） | 只需空表结构，自行录入数据 |
| `cmd_schema_subset.sql` | CMD 业务相关 93 张表子集 DDL（仅结构，无数据） | 只需 CMD 模块相关表 |

> **推荐使用 `db_full_dump.sql`**，它包含建库语句、全部表结构和全部业务数据，一条命令即可完成导入。

---

## 三、导入方式

### 方式一：命令行导入完整数据（推荐）

```bash
# 直接导入完整 dump（文件内含 CREATE DATABASE 和 USE 语句，无需手动建库）
mysql -uroot -p < sql/db_full_dump.sql
```

输入 MySQL root 密码后等待导入完成。导入后将创建 `ruoyi_plus_py` 数据库，含 64 张表和全部业务数据。

#### 验证导入结果

```bash
# 检查表数量（应为 64）
mysql -uroot -p -e "SELECT COUNT(*) AS table_count FROM information_schema.tables WHERE table_schema='ruoyi_plus_py' AND table_type='BASE TABLE';"

# 检查业务数据（例如客户表）
mysql -uroot -p -e "SELECT COUNT(*) AS customer_count FROM ruoyi_plus_py.cmd_customer;"
```

预期输出：
```
table_count
64

customer_count
28
```

---

### 方式二：命令行仅导入表结构（无业务数据）

```bash
# 1) 创建数据库
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS ruoyi_plus_py DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;"

# 2) 导入表结构（119 表 DDL，无数据）
mysql -uroot -p ruoyi_plus_py < sql/db_schema.sql
```

如仅需 CMD 业务相关表：
```bash
mysql -uroot -p ruoyi_plus_py < sql/cmd_schema_subset.sql
```

---

### 方式三：使用 GUI 工具导入

#### Navicat

1. 打开 Navicat，连接本地 MySQL
2. 右键连接 → 「运行 SQL 文件...」
3. 选择 `sql/db_full_dump.sql`
4. 点击「开始」执行
5. 完成后在左侧刷新，应看到 `ruoyi_plus_py` 数据库及 64 张表

#### DBeaver

1. 打开 DBeaver，连接本地 MySQL
2. 菜单 「SQL 编辑器」→ 「运行 SQL 脚本」
3. 选择 `sql/db_full_dump.sql`
4. 执行脚本
5. 刷新数据库列表，应看到 `ruoyi_plus_py` 数据库

#### MySQL Workbench

1. 打开 MySQL Workbench，连接本地 MySQL
2. 菜单 「File」→ 「Open SQL Script」
3. 选择 `sql/db_full_dump.sql`
4. 点击闪电图标执行全部脚本
5. 刷新左侧 Schema 列表，应看到 `ruoyi_plus_py` 数据库

## 四、导入后配置

### 4.1 后端数据库连接

确保 `backend/.env` 文件中数据库配置与本地 MySQL 一致：

```env
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=<你的MySQL密码>
DB_NAME=ruoyi_plus_py
DB_CHARSET=utf8mb4
```

> 如不存在 `.env` 文件，从 `backend/.env.example` 复制一份并修改密码。

### 4.2 默认登录账号

导入完整数据后，系统内置以下账号：

| 用户名 | 密码 | 角色 |
|--------|------|------|

| `test` | `admin123` | 测试用户 |
| `test1` | `admin123` | 测试用户 |

> 密码在数据库中以 bcrypt hash 存储，非明文。

## 六、常见问题

### Q1：导入时报 "Unknown database 'ruoyi_plus_py'"

`db_full_dump.sql` 内含 `CREATE DATABASE` 语句，无需手动建库。如使用 `db_schema.sql` 则需先手动建库（见方式二第 1 步）。

### Q2：导入时报 "Access denied"

确认 MySQL 用户有足够权限（建议使用 root 账户，或拥有 CREATE、INSERT、INDEX、ALTER、TRIGGER 权限的账户）。

### Q3：导入后中文乱码

确保 MySQL 连接字符集为 `utf8mb4`。命令行导入时添加参数：
```bash
mysql -uroot -p --default-character-set=utf8mb4 < sql/db_full_dump.sql
```

### Q4：导入后表数量不是 64

`db_full_dump.sql` 导出时数据库为 64 张表。如使用 `db_schema.sql` 则为 119 张表（含部分空表）。两者表数量不同是正常现象，不影响使用。

### Q5：如何重新导出最新数据

如本地数据库有更新需重新导出：
```bash
mysqldump -uroot -p --databases ruoyi_plus_py --default-character-set=utf8mb4 --single-transaction --routines --triggers --events --no-tablespaces --complete-insert > sql/db_full_dump.sql
```

## 七、快速开始（完整流程）

```bash
# 1. 导入数据库（一条命令搞定）
mysql -uroot -p < sql/db_full_dump.sql

# 2. 配置后端环境
cp backend/.env.example backend/.env
# 编辑 backend/.env，修改 DB_PASSWORD 为你的 MySQL 密码

# 3. 启动后端
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --reload --port 8000

# 4. 启动前端（新终端）
cd frontend
pnpm install
pnpm dev

# 5. 访问系统
# 浏览器打开 http://localhost:5173
# 使用 admin / admin123 登录
```
